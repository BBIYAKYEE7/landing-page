# 의뢰 폼 저장·알림 설정 안내 (Google Apps Script)

회사 사이트 의뢰 페이지(`/request`)로 들어온 의뢰를 **비공개 Google 스프레드시트**에 한 줄씩 저장하고 **메일로 알려 주는** 장치입니다. 비용은 0원이고, 처음 한 번 설정하는 데 20~30분 걸립니다.

## 어떻게 동작하나요

```text
의뢰 페이지 → 사이트 서버(Vercel, /api/request)에서 검사 → Apps Script 웹 앱(이 폴더의 코드)
                                                        ├─ 스프레드시트에 한 줄 저장
                                                        └─ 운영자 메일 (선택: Slack, 의뢰자 자동 회신)
```

- 사이트 서버와 이 스크립트만 아는 비밀값(SECRET)이 맞아야 저장됩니다. 비밀값이 틀린 요청은 모두 거절합니다.
- 접수 번호는 `UT-20261105-0001`처럼 한국 날짜와 그날의 순번으로 만듭니다.
- 같은 의뢰가 실수로 두 번 전송돼도 10분 안이면 한 줄만 저장하고 같은 접수 번호를 돌려줍니다. 내용을 고쳐 다시 보낸 경우에도 처음 내용만 남으니, 그때는 실행 기록의 `duplicate_payload_mismatch`(맨 아래 표)를 보고 의뢰자에게 확인하세요.
- 웹 앱 주소를 브라우저로 열면 `ok`만 보입니다. 저장된 내용은 주소로 볼 수 없습니다.

## 준비물

- Google 계정 1개: 의뢰를 보관하고 알림 메일을 보낼 계정입니다. 회사 메일(`u-teed.co.kr`)은 Google Workspace가 아니라 메일플러그를 씁니다. 그래서 회사가 공용으로 관리할 Gmail 계정을 새로 만들어 쓰기를 권합니다. 비밀번호와 2단계 인증 수단은 회사가 보관하세요. 담당자 개인 계정을 쓰면 담당자가 바뀔 때 의뢰 보관·파기를 회사가 통제하기 어렵습니다.
- Vercel 프로젝트 설정 권한
- Mac 터미널 (비밀값 만들기, 시험)
- 이 폴더의 파일 2개: `Code.gs`, `appsscript.json`

## 1. 새 스프레드시트 만들기

1. 준비물의 Google 계정으로 로그인한 브라우저에서 https://sheets.new 를 엽니다.
2. 왼쪽 위 제목을 `U-TEED 의뢰 접수`처럼 바꿉니다.
3. 주소창의 주소에서 `/d/`와 `/edit` 사이 값(스프레드시트 ID)을 복사해 둡니다. 5단계 `SHEET_ID`에 넣습니다.
   - 예: `https://docs.google.com/spreadsheets/d/`**`1AbC…xYz`**`/edit`
4. 이 스프레드시트는 **누구와도 공유하지 마세요.** 편집 권한이 있으면 의뢰 내용을 모두 볼 수 있습니다.

## 2. Apps Script 프로젝트 만들기

1. 같은 Google 계정으로 https://script.google.com 을 열고 왼쪽 위 **새 프로젝트**를 누릅니다.
2. 편집기가 열립니다. 왼쪽 위 `제목 없는 프로젝트`를 눌러 `U-TEED 의뢰 접수`로 바꿉니다.

이 스크립트는 스프레드시트에 묶지 않은 독립 프로젝트입니다. 어느 파일에 저장할지는 5단계 `SHEET_ID`로 정합니다. 그래서 파기하며 저장 파일을 바꿔도 웹 앱 주소가 그대로입니다('운영할 때'). 이 프로젝트도 누구와도 공유하지 마세요. 편집 권한이 있으면 SECRET을 볼 수 있습니다.

## 3. Code.gs 붙여 넣기

1. GitHub에서 `integrations/google-apps-script/Code.gs` 파일을 열고 오른쪽 위 **Copy raw file**(복사 아이콘)을 누릅니다.
2. Apps Script 편집기 왼쪽 파일 목록에서 `Code.gs`를 엽니다.
3. 원래 있던 `function myFunction() { … }`을 모두 지우고(⌘A, Delete) 복사한 내용을 붙여 넣습니다(⌘V).
4. 저장합니다(⌘S 또는 디스크 아이콘).

## 4. appsscript.json 붙여 넣기

1. 왼쪽 맨 아래 톱니바퀴 **프로젝트 설정**을 누릅니다.
2. **편집기에서 'appsscript.json' 매니페스트 파일 표시**에 체크합니다.
3. 왼쪽 **편집기**(`< >` 아이콘)로 돌아가면 파일 목록에 `appsscript.json`이 보입니다. 엽니다.
4. 안의 내용을 모두 지우고, 이 폴더의 `appsscript.json` 내용을 붙여 넣은 뒤 저장합니다.

이 파일은 시간대를 한국으로 맞추고, 권한을 세 가지(스프레드시트, 메일 보내기, 외부 주소 호출)로 줄입니다. 스프레드시트 권한은 이 계정의 모든 스프레드시트에 미치므로, 이 스크립트는 의뢰 전용 계정에서만 쓰세요.

## 5. 스크립트 속성 넣기

### SECRET 만들기

SECRET은 사이트 서버와 이 스크립트만 아는 긴 무작위 문자열입니다.

1. Mac에서 **터미널**을 엽니다(⌘Space, "터미널" 입력).
2. 아래를 붙여 넣고 Enter를 누릅니다.

   ```bash
   openssl rand -hex 32
   ```

3. 나온 64자(숫자와 a~f)를 복사해 비밀번호 관리자 같은 곳에 보관합니다. 8단계에서 Vercel에도 같은 값을 넣습니다.

터미널이 어렵다면 비밀번호 관리자(1Password, Bitwarden, Chrome 비밀번호 생성기 등)로 만든 영문·숫자 32자 이상 문자열을 써도 됩니다.

### 속성 넣기

1. **프로젝트 설정** 화면 맨 아래 **스크립트 속성**에서 **스크립트 속성 추가**를 누릅니다(이미 있으면 **스크립트 속성 수정**).
2. 아래 표대로 넣고 **스크립트 속성 저장**을 누릅니다. 쓰지 않을 선택 항목은 아예 만들지 않으면 기본값으로 동작합니다.

| 속성 | 값 | 필요 여부 |
|---|---|---|
| `SECRET` | 위에서 만든 64자 | **필수.** 없으면 모든 접수를 거절합니다 |
| `SHEET_ID` | 1단계에서 복사한 스프레드시트 ID. 주소 전체를 넣어도 됩니다 | **필수.** 없거나 틀리면 접수를 저장하지 못합니다 |
| `NOTIFY_EMAIL` | 알림 받을 주소. 여러 개면 쉼표(,)로 구분 | 선택. 없으면 `taeho@u-teed.co.kr` |
| `SLACK_WEBHOOK_URL` | Slack Incoming Webhook 주소(`https://hooks.slack.com/...`) | 선택. 없으면 Slack 알림을 보내지 않습니다 |
| `AUTO_REPLY` | `true` | 선택. `true`일 때만 의뢰자에게 접수 확인 메일을 보냅니다. 없으면 꺼짐 |
| `SHEET_NAME` | 저장할 시트(탭) 이름 | 선택. 없으면 `의뢰` |

- `AUTO_REPLY`는 아래 위험을 알고 켜세요. 자동 회신은 폼에 적힌 이메일 주소로 우리 계정에서 보내는 이름 `U-TEED`로 나가고, 본문에 제출자가 쓴 한 줄 소개·자세한 내용(최대 5,000자)·참고 링크가 그대로 들어갑니다. 누구나 남의 주소를 적어 낼 수 있으므로, 켜 두면 다른 사람이 쓴 광고·피싱 문구와 링크를 우리 이름으로 아무에게나 보내는 통로가 될 수 있습니다. 받은 사람이 스팸으로 신고하면 이 계정의 메일 발송이 막힐 수도 있습니다. 또 운영자 알림과 같은 하루 메일 한도(11단계)를 나눠 씁니다. **사이트 서버(`/api/request`)에 요청 횟수 제한이 없으면 켜지 마세요.**
- 켜 두어도 스크립트가 자동 회신을 하루(한국 시간) 20통까지만 보내고, 같은 주소에는 6시간에 1통만 보냅니다. 운영자 메일을 보낸 뒤 남은 하루 메일 한도가 20 이하이면 운영자 알림 몫으로 남겨 두고 보내지 않습니다. 건너뛴 회신은 **실행** 기록에 `notify_skipped auto_reply`로 남고(맨 아래 표), 시트 저장과 운영자 알림은 그대로 됩니다.
- Slack 알림을 쓰려면 Slack에서 Incoming Webhook을 만들어 주소를 받습니다(https://api.slack.com/messaging/webhooks).
- 접수가 들어오면 `RECEIPT_COUNTER_20261105` 같은 속성이 저절로 생깁니다. 접수 번호를 세는 값이니 고치거나 지우지 마세요. 지난 날짜 것은 스크립트가 알아서 지웁니다.
- `AUTO_REPLY`를 켜면 그날 보낸 자동 회신 수를 세는 `AUTO_REPLY_COUNTER` 속성(값 예: `20261105:3`)도 저절로 생깁니다. 이것도 고치거나 지우지 마세요.

## 6. setup 실행하고 권한 승인하기

1. 왼쪽 **편집기**(`< >` 아이콘)의 파일 목록에서 `Code.gs`를 다시 엽니다(함수 선택 칸에는 지금 열린 파일의 함수만 보입니다). 위쪽 도구 모음의 함수 선택 칸에서 **setup**을 고르고 **실행**을 누릅니다.
2. "승인 필요" 창에서 **권한 검토**를 누르고 스프레드시트를 만든 그 Google 계정을 고릅니다.
3. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급**을 누르고 **U-TEED 의뢰 접수(으)로 이동(안전하지 않음)**을 누릅니다. 직접 만든 스크립트라서 나오는 화면입니다.
4. 권한 목록(Google 스프레드시트 보기·수정·만들기·삭제, 내 이름으로 메일 보내기, 외부 서비스 연결)을 **모두 허용**합니다. 체크박스가 보이면 모두 선택한 뒤 계속을 누릅니다.
5. 아래 **실행 로그**에 `준비 완료`와 설정 요약이 나오면 성공입니다. `저장할 파일`이 1단계 스프레드시트인지 확인합니다. 그 스프레드시트에 `의뢰` 탭과 1행 열 이름이 생깁니다.

빨간 오류에 `SECRET`이나 `SHEET_ID`가 보이면 5단계 속성 이름(대문자)과 값을 확인하고 다시 실행하세요.

## 7. 웹 앱으로 새 배포하고 URL 복사하기

1. 오른쪽 위 **배포 > 새 배포**를 누릅니다.
2. **유형 선택** 옆 톱니바퀴에서 **웹 앱**을 고릅니다.
3. 설명: `의뢰 접수`
4. **다음 사용자 인증 정보로 실행: 나(내 이메일)**
5. **액세스 권한이 있는 사용자: 모든 사용자**
   - 사이트 서버(Vercel)가 로그인 없이 보내려면 "모든 사용자"여야 합니다. 비밀값이 맞지 않으면 아무것도 저장되지 않으니 안전합니다.
6. **배포**를 누릅니다(권한을 다시 물으면 6단계처럼 허용). **웹 앱 URL** 옆 **복사**를 누릅니다.
   - 주소는 `https://script.google.com/macros/s/…/exec`처럼 `/exec`로 끝나야 합니다.
7. 복사한 주소를 브라우저 새 탭에서 열어 `ok`만 보이면 배포가 된 것입니다.

Google Workspace 계정에서 "모든 사용자"가 보이지 않으면 관리 콘솔에서 외부 공유를 막아 둔 것입니다. 관리자에게 이 웹 앱만 허용해 달라고 요청하세요. 준비물대로 새로 만든 회사 공용 Gmail 계정에는 이 제한이 없습니다. 어느 계정이든 담당자 개인 계정은 피하세요. 의뢰자 개인정보(이름·이메일·전화·의뢰 내용)와 SECRET이 회사가 관리하지 않는 계정에 쌓이고, 담당자가 바뀌면 보관·파기를 회사가 통제하기 어렵습니다.

## 8. Vercel 환경변수 넣고 다시 배포하기

1. Vercel에서 이 사이트 프로젝트를 열고 **Settings > Environment Variables**로 갑니다.
2. 아래 두 개를 추가합니다. Environments는 **Production**을 고릅니다(미리보기 주소에서도 시험하려면 **Preview**도).

   | Key | Value |
   |---|---|
   | `REQUEST_ENDPOINT_URL` | 7단계에서 복사한 웹 앱 URL |
   | `REQUEST_ENDPOINT_SECRET` | 5단계 SECRET과 **똑같은 값** (Sensitive를 켜 두기를 권장) |

3. **Save**를 누릅니다.
4. 환경변수는 새로 배포할 때부터 적용됩니다. **Deployments**에서 맨 위 Production 배포 오른쪽 **⋯ > Redeploy**를 누릅니다.

이름 앞에 `NEXT_PUBLIC_`을 붙이면 값이 브라우저에 노출됩니다. 위 이름 그대로 쓰세요.

## 9. curl로 시험하기

터미널에서 순서대로 합니다.

1. 아래 줄을 붙여 넣고 Enter를 누른 다음, SECRET 값을 붙여 넣고 다시 Enter를 누릅니다. 입력한 값은 화면에 보이지 않습니다.

   ```bash
   read -rs SECRET
   ```

2. 아래 줄의 주소 부분을 7단계 웹 앱 URL로 바꿔 붙여 넣고 Enter를 누릅니다.

   ```bash
   URL='https://script.google.com/macros/s/여기에_배포_ID/exec'
   ```

3. 아래 블록을 통째로 붙여 넣고 Enter를 누릅니다. 본문은 셸에 내장된 `printf`가 curl에 표준입력으로 넘기므로, SECRET이 다른 사용자가 볼 수 있는 프로세스 목록(`ps`)에 나타나지 않습니다.

   ```bash
   printf '%s' '{
     "secret": "'"$SECRET"'",
     "idempotency_key": "setup-test-0001",
     "data": {
       "category": "아직 모르겠어요", "services": [],
       "title": "설정 확인용 시험 접수",
       "description": "Apps Script 연결을 확인하려고 보내는 시험 접수입니다. 확인한 뒤 이 행은 지워도 됩니다.",
       "stage": "아이디어만 있음", "references": [],
       "platforms": [], "features": [], "scope": [],
       "purpose": null, "program_name": null, "deadline": null, "draft": null,
       "timeline": "협의", "budget": "아직 못 정함",
       "name": "시험", "company": null, "email": "taeho@u-teed.co.kr", "phone": null, "source": null
     }
   }' | curl -sS -L -H 'Content-Type: application/json' --data-binary @- "$URL"
   ```

   다 쓴 뒤에는 `unset SECRET`으로 셸에서 값을 지웁니다.

4. 아래처럼 나오면 성공입니다. 스프레드시트 `의뢰` 탭에 한 줄이 생기고 운영자 메일이 옵니다.

   ```text
   {"ok":true,"receipt_no":"UT-20261105-0001","received_at":"2026-11-05T14:03:00+09:00"}
   ```

- 10분 안에 3번을 다시 실행하면 같은 접수 번호가 나오고 새 줄은 생기지 않습니다(중복 방지 확인).
- 비밀값 거절 확인: `SECRET=wrong`을 실행한 뒤 3번을 다시 실행하면 `{"ok":false,"error":"UNAUTHORIZED","message":"unauthorized"}`가 나옵니다.
- 명령에 `-X POST`를 붙이지 마세요. Apps Script는 결과를 다른 주소로 넘겨주는데(302), `-X POST`가 있으면 그 주소에도 POST를 보내 오류가 납니다.
- 시험한 줄은 지워도 됩니다. 접수 번호는 다시 쓰지 않으므로 그날 실제 첫 의뢰가 `0002`로 시작해도 정상입니다.
- 마지막으로 사이트의 `/request`에서 직접 의뢰를 보내, 완료 화면의 접수 번호가 시트에 있는지 확인합니다.

## 10. 코드를 고친 뒤 배포 관리에서 새 버전으로 갱신하기 (URL 유지)

## 12. 개인정보 처리방침

사이트 `/privacy`(내용은 `src/content/privacy.ts`)에 이 장치의 처리 위탁(Google, Vercel, 메일플러그), 국외 이전(Google, Vercel), 보유 기간, 파기 절차를 적어 두었습니다. 아래 '운영할 때' 절차는 그 문구에 맞춘 것입니다. 다음을 바꾸기 전에는 `/privacy`를 먼저 고치세요.

- Slack 알림(`SLACK_WEBHOOK_URL`) 켜기: Slack을 처리 위탁·국외 이전에 더하고, 파기에 메시지 삭제를 더합니다.
- 자동 회신(`AUTO_REPLY`) 켜기: Google에 맡기는 업무에 접수 확인 메일 발송을 더하고, 파기에 Gmail 보낸편지함의 자동 회신 사본을 더합니다.
- `NOTIFY_EMAIL`에 주소를 더하거나 운영을 다른 사람에게 맡기기: 처리방침의 '다루는 사람'과 파기하는 사람을 고치고, 그 메일함도 정리·파기 대상에 넣습니다.
- 알림 받는 주소(`NOTIFY_EMAIL`)를 메일플러그가 아닌 메일로 바꾸기: 수탁자를 바꿉니다.
- 의뢰를 보관하는 Google 계정이나 '운영할 때' 절차 바꾸기.

- 여러 개 고른 항목은 `, `로 이어 붙입니다. 고른 분야와 관계없는 칸과 적지 않은 칸은 비어 있습니다.

- X열에 드롭다운(데이터 확인)을 아래까지 미리 채워 두어도 새 의뢰는 A열(`receipt_no`)이 채워진 마지막 줄 바로 아래에 들어갑니다. A~V열의 순서는 바꾸지 마세요.
- A~V열의 빈 줄에 손으로 무언가 적어 두면, 그 줄을 덮어쓰지 않으려고 새 의뢰를 시트에서 내용이 있는 마지막 줄 아래에 씁니다.
- 줄을 지울 때는 내용만 지우지 말고 행 번호를 오른쪽 클릭해 **행 삭제**를 쓰세요. 맨 아래 의뢰 줄의 A~V열만 비우면 다음 의뢰가 그 줄에 들어가고, 그 줄의 W·X열은 그대로 남습니다.
- 1행 열 이름을 한국어로 바꿔도 저장에는 문제없습니다.
- 탭 이름을 바꾸면 `SHEET_NAME` 속성도 같이 바꾸세요. 그러지 않으면 `의뢰` 탭이 새로 생깁니다.

### 운영할 때

처리방침(`/privacy`)의 보유 기간·파기 문구대로 하는 절차입니다. 이 절차는 대표(개인정보 보호책임자)가 합니다. 의뢰 내용은 상담하는 동안만 Google(시트·Gmail)에 둡니다. 상담이 끝나면 Google 사본을 지우고, 1년 동안 회사 메일함(메일플러그)에만 둡니다. 접수 번호나 의뢰자 이름을 Google 캘린더 같은 다른 곳에 적지 않습니다.

**상담 종료일**은 회사나 의뢰자가 상담을 마치겠다고 알린 날입니다. 그런 연락이 없으면 마지막 연락 뒤 30일이 지난 날입니다(처리방침과 같음).

- **처음 한 번**: 시트 W1 칸에 `마지막 연락일`, X1 칸에 `진행 상태`를 적습니다. 회사 메일함(메일플러그)에 `상담 중`, `보존` 메일함을 만듭니다.
- **접수 알림 메일이 오면**: 시트 W열에 그날 날짜를 적고, 알림 메일을 `상담 중` 메일함으로 옮깁니다. 이메일로만 온 의뢰·문의도 `상담 중`으로 옮깁니다.
- **연락을 주고받을 때마다**: W열 날짜를 그날로 고칩니다. 받은 메일과 보낸 회신(보낸메일함)을 모두 `상담 중`에 둡니다.
- **상담이 끝난 의뢰 정리**: 상담을 마치기로 한 의뢰는 그날 합니다. 연락이 끊긴 의뢰는 **매주 월요일**(공휴일이면 다음 영업일)에 찾아서 합니다. W열(비어 있으면 B열 접수일)이 3주(21일) 넘게 지난 줄과, `상담 중` 메일함에서 마지막 메일이 3주 넘게 지난 대화가 대상입니다. 그러면 마지막 연락 뒤 22~32일에 정리하므로 처리방침의 기한(상담 종료일부터 5일) 안에 끝납니다.
  - ① 상담 종료일(마치기로 한 날, 또는 마지막 연락일에 30일을 더한 날)에서 1년 뒤의 달을 정합니다. 예: 상담 종료일이 2026-12-14이면 2027-12.
  - ② 시트에서 그 줄의 A열 접수 번호를 확인해 둡니다.
  - ③ 회사 메일함(메일플러그)에서 그 의뢰의 알림 메일과 주고받은 메일(보낸메일함의 회신 포함)을 ①에서 정한 달의 `파기 YYYY-MM` 메일함(예: `파기 2027-12`)으로 옮깁니다. 없으면 만듭니다.
  - ④ 이 Google 계정 Gmail에서 ②의 접수 번호로 검색해 **보낸편지함**의 운영자 메일 사본, 자동 회신 사본(켠 경우), 반송 메일을 지우고 휴지통을 비웁니다.
  - ⑤ Slack 알림을 켰다면 그 메시지도 지웁니다.
  - ⑥ 시트에서 그 줄을 **행 삭제**합니다.

  이메일로만 받은 의뢰는 ①과 ③만 합니다. 정리한 뒤 다시 연락이 오면 메일을 `상담 중`으로 되돌리고 이메일로 상담을 이어 갑니다. 시트에 다시 적지는 않습니다.
- **매월 5일까지**(보통 1~5일에 합니다. 그사이 영업일이 없으면 전달 마지막 영업일에 미리 하고, 그때는 다음 달 이름의 메일함을 비웁니다):
  - 회사 메일함(메일플러그)에서 그달 이름의 `파기 YYYY-MM` 메일함에 있는 메일을 모두 지우고 휴지통을 비웁니다. 빠뜨린 것이 없는지 받은편지함, 보낸메일함, `상담 중`에서 마지막 메일이 11개월 넘게 지난 의뢰·문의도 찾아 같이 지웁니다. `보존` 메일함은 건드리지 않습니다.
  - 아래 '파일 바꾸기'로 스프레드시트 버전 기록을 정리합니다.
- **파일 바꾸기**(버전 기록 정리): 스프레드시트는 지운 줄도 **버전 기록**에 남깁니다. 그래서 파일을 사본으로 바꿉니다. 웹 앱 주소와 Vercel 설정은 그대로 둡니다.
  - ① 접수가 드문 시간에 저장 중인 파일을 열고 **파일 > 사본 만들기**를 누릅니다. 이름을 `U-TEED 의뢰 접수 2026-12-03`처럼 오늘 날짜로 바꿉니다. 사본에는 버전 기록이 넘어가지 않습니다.
  - ② 새 탭에 열린 사본의 주소에서 ID를 복사합니다. Apps Script **프로젝트 설정 > 스크립트 속성**에서 `SHEET_ID`를 이 값으로 바꾸고 저장합니다.
  - ③ 편집기에서 **setup**을 실행합니다. 실행 로그의 `저장할 파일`이 ①에서 붙인 이름이고, 주소가 사본 탭의 주소와 같은지 확인합니다.
  - ④ 원래 파일 탭(사본을 만든 탭)에서 마지막 줄 접수 번호가 사본에도 있는지 봅니다. ①과 ② 사이에 들어온 접수가 있으면 그 줄을 사본에 옮겨 적습니다.
  - ⑤ 원래 파일 탭에서 **파일 > 휴지통으로 이동**을 누릅니다. 아직 휴지통은 비우지 않습니다.
  - ⑥ **setup**을 한 번 더 실행해 `저장할 파일`이 ③과 같은지 확인합니다. 오류가 나면 Google Drive 휴지통에서 그 파일을 복원하고, `SHEET_ID`를 남아 있는 파일로 되돌린 뒤 ①부터 다시 합니다.
  - ⑦ Google Drive 휴지통에 든 파일이 ③에서 확인한 이름·주소가 아닌지 확인한 뒤 휴지통을 비웁니다.
- **열람·정정·삭제·처리정지 요구나 국외 이전을 원하지 않는다는 연락을 받으면 10일 안에**:
  - ① 본인인지 확인합니다. 의뢰에 적은 이메일 주소에서 온 연락이면 됩니다. 서면이나 대리인이면 신분증 사본이나 위임장(「개인정보 처리 방법에 관한 고시」 별지 제11호 서식)으로 확인합니다. 의뢰에 이메일 주소를 잘못 적은 사람은 접수 시각, 한 줄 소개, 전화번호처럼 본인만 아는 내용으로 확인하고, 어떻게 확인했는지 회신 메일에 남깁니다. 접수 번호만으로 본인을 확인하지 않습니다.
  - ② 열람이면 시트와 메일에 있는 그 사람의 정보를 정리해 보냅니다. 정정이면 시트의 그 칸을 고칩니다.
  - ③ 삭제·처리정지나 국외 이전을 원하지 않는 경우: '상담이 끝난 의뢰 정리'의 ②, ④, ⑤, ⑥으로 Google 사본을 지우고, '파일 바꾸기'를 한 번 더 합니다.
  - ④ 삭제·처리정지 요구이면 회사 메일함(메일플러그)에서도 그 의뢰의 메일을 지우고 휴지통을 비웁니다. 요구 메일은 남깁니다.
  - ⑤ 결과를 요구 메일에 대한 답장(서면이면 알려 준 주소)으로 알립니다. 요구 메일과 이 회신은 처리한 날에서 1년 뒤 달의 `파기 YYYY-MM` 메일함으로 옮깁니다. 국외 이전만 원하지 않으면 상담은 이메일로 이어 갑니다.
- **수사·조사 통보를 받으면**: 그 의뢰의 메일을 `보존` 메일함으로 옮겨 정리·파기에서 뺍니다. 끝나면 그날을 상담 종료일로 보고 '상담이 끝난 의뢰 정리'를 합니다.
- 비밀값을 바꿀 때(유출이 의심될 때): 새 값 만들기, 스크립트 속성 `SECRET` 수정, Vercel `REQUEST_ENDPOINT_SECRET` 수정, Vercel Redeploy 순서로 합니다. 두 값이 다른 몇 분 동안은 접수가 실패하고, 사이트는 이메일로 연락하라는 안내를 보여 줍니다.

### 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| `"error":"UNAUTHORIZED"` | `SECRET`과 `REQUEST_ENDPOINT_SECRET`이 똑같은지, 속성 이름이 대문자 `SECRET`인지 |
| curl 결과가 HTML(로그인·오류 페이지) | 7단계 액세스가 "모든 사용자"인지, URL이 `/exec`로 끝나는지, `-X POST`를 넣지 않았는지 |
| `"error":"VALIDATION"` | `message`에 적힌 항목 이름 |
| `"error":"SERVER"`, `"message":"busy, please retry"` | 요청이 한꺼번에 몰림. 잠시 뒤 다시 시도 |
| 사이트에서 접수 실패 안내가 나옴 | Vercel 환경변수 두 개와 Redeploy 여부, Apps Script 왼쪽 **실행** 기록(`sheet_open_failed`가 있으면 `SHEET_ID`), 편집기에서 setup을 실행했을 때 오류가 나는지 |
| 메일이 오지 않음 | 스팸함, `NOTIFY_EMAIL` 오타, **실행** 기록의 `notify_failed` |
| 의뢰자가 접수 확인 메일을 받지 못함 | `AUTO_REPLY`가 `true`인지, **실행** 기록의 `notify_skipped auto_reply`(아래 표) |

Apps Script 왼쪽 **실행** 기록에는 접수 번호와 오류 종류만 남고, 의뢰 내용은 남지 않습니다.

| 기록 | 뜻 |
|---|---|
| `saved UT-…` | 저장됨 |
| `duplicate UT-…` | 같은 의뢰를 다시 받음. 새 줄 없음 |
| `duplicate_payload_mismatch UT-…` | 같은 의뢰를 다시 받았는데 내용이 처음과 다름(실패 안내를 보고 고쳐서 다시 보낸 경우 등). 시트와 알림에는 처음 내용만 있으니 의뢰자에게 이메일·연락처와 내용을 확인하세요 |
| `rejected unauthorized` | 비밀값이 틀림 |
| `rejected validation title,email` | 검사에 걸린 항목 |
| `honeypot_dropped` | 스팸 로봇으로 보고 저장하지 않음(사이트 서버가 먼저 걸러서, 보통은 웹 앱을 직접 부른 요청에만 남음) |
| `notify_failed operator_email UT-… mail_quota_exhausted` | 메일 한도 초과. 시트에는 저장됨 |
| `notify_skipped auto_reply UT-… daily_limit` | 오늘 자동 회신 20통을 다 써서 보내지 않음. 저장·운영자 알림은 됨 |
| `notify_skipped auto_reply UT-… recently_sent` | 같은 주소로 6시간 안에 자동 회신을 보내서 이번에는 보내지 않음 |
| `notify_skipped auto_reply UT-… quota_reserved` | 남은 메일 한도를 운영자 알림 몫으로 남기려고 보내지 않음 |
| `notify_skipped auto_reply UT-… unsupported_address` | 이메일에 쉼표 같은 글자가 있어 보내지 않음(운영자 메일의 답장 주소도 비움) |
| `save_failed UT-… Exception` | 저장 실패. 그 번호는 비고, 의뢰자에게는 실패 안내가 나감 |
| `save_failed - Error` | 저장하기 전에 실패(접수 번호는 쓰지 않음). 바로 위 줄에 원인(`sheet_open_failed` 등)이 있음 |
| `sheet_open_failed - missing_sheet_id` | 스크립트 속성 `SHEET_ID`가 없음. 5단계대로 넣고 setup으로 `저장할 파일`을 확인 |
| `sheet_open_failed - Exception` | `SHEET_ID` 파일을 열지 못함. 값이 맞는지, 그 파일이 휴지통에 있거나 지워지지 않았는지 보고 setup을 실행 |
